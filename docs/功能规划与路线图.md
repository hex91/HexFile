# 功能规划与路线图（HexFile 本地工具集）

> 纯功能视角。本文描述「HexFile」这款**纯本地 Android 工具集**的功能范围、完成度与下一步规划。
> 原则：**无网络、无账号、无 VIP、无统计、无云备份**——所有能力都在设备上完成。
> 复用成熟开源组件（Termux 终端引擎、NanoHTTPD、Nayuki QR、sevenzipjbinding、zstd-jni 等），不重复造轮子。
>
> 早期曾有一版「逆向分析 / 对标分析」文档，现已本地归档，不再作为规划依据；本文独立以功能视角编写。

## 二、下一步候选方向（按性价比排序）

### A. 文件管理增强（低风险，直接补完骨架）
- 三种对比模式（文件夹 / 文本 / 哈希，差异分色高亮）
- 文件加密 / 解密（AES 对称，独立文件级）
- 高级搜索（通配符 / 正则 / 大小 / 时间 / 类型）
- **价值**：补齐文件管理最核心的缺口，与现有双栏 / 批量能力天然契合。

### B. 网络存储挂载（功能性强）
- SMB / WebDAV / FTP / SFTP 客户端，直接访问电脑共享或网盘
- **价值**：与已有「局域网远程管理」互补，构成完整的「设备 ↔ 电脑」文件通路。
- **注意**：需评估开源库在 targetSdk 30 下的兼容性。

### C. 媒体与文档工具（面向日常使用，受众广）
- 图片批量处理（缩放 / 格式转换 / 水印）
- PDF 预览 / 标注
- 视频缩略图 / 取色器 / 字体预览
- **价值**：把工具从「逆向向」扩展到「日常向」，提升使用频率。

### D. 应用管理二期（在现有能力上纵向加深）
- 应用备份 / 还原（含数据）—— **已完成**
- 系统应用冻结 —— **基本完成**
- 权限管理可视化 —— **已完成（危险权限批量授予 / 撤销）**
- 其余扩展示例：备份管理界面、按备份批量还原、非危险权限细粒度控制

### E. APK 增强（逆向能力补强）
- 改包名共存（应用多开）
- APK 对比（版本差异）
- 点九图 / SVG 编辑、Jar/DEX 互转
- **价值**：面向进阶逆向用户，工程量中等偏上。

### F. 终端增强二期
- 脚本执行器（JS 引擎）
- 自定义解密函数（配合文件加密）
- **价值**：把终端从「交互 shell」升级为「可编程工具」。

### G. 历史版本回归（质量兜底，非新功能）
- 对早期未经真机实测的版本（格式化、批量重命名、HEX 增强、加密 ZIP、SigKill、分割合并）做一轮回归，确认无隐患。

## 三、实施原则

1. **纯本地优先**：任何新功能默认离线可用；联网能力仅限于「局域网内你自己设备的互访」。
2. **复用开源、避免重复造轮子**：终端（Termux）、HTTP（NanoHTTPD）、二维码（Nayuki）、压缩（sevenzipjbinding / zstd-jni）等已成例，后续继续此路线。
3. **低风险高收益先行**：优先补完已有骨架的缺口（如文件对比、加密），再上独立大模块（如网络存储、媒体）。
4. **CI 自动出包**：推 `main` 自动编译并发布到 Release 的 `continuous`；打 `v*` 标签发布正式 Release，APK 可直接下载安装。
5. **签名稳定**：发布密钥库不进仓库，通过仓库 Secrets 注入；统一为别名 `hex91`，与已装 APK 同签名、可原地升级。

## 四、发版流程（备忘）

```
改 AndroidManifest.xml 的 versionName / versionCode
   → git commit
   → git tag vX.Y.Z && git push --tags
   → CI 自动构建并发布正式 Release（附签名 APK）
推 main（不带标签）→ CI 发布到 continuous（预发布）供尝鲜
```
